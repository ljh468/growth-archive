## 0. 이 문서의 역할

### 0.1 이 문서가 결정하는 것

본 문서는 Growth Archive MVP에서 사용자가 어떤 화면을 어떤 순서로 이동하며, 각 화면에서 무엇을 보고 무엇을 할 수 있는지를 정의한다.

구체적으로 다음을 결정한다.

1. 전체 IA와 사이트맵
2. URL 구조와 라우팅 규칙
3. PC 상단 내비게이션
4. 모바일 하단 내비게이션
5. Guest / Kakao User / Member / Admin별 화면 접근 정책
6. 공개 화면과 멤버 전용 화면의 구분
7. 주요 사용자 흐름
8. 화면별 목적, 진입 경로, 노출 정보, CTA, 빈 상태, 에러 상태
9. 모바일 웹뷰 기준 화면 정책
10. Codex가 프론트엔드 라우팅과 화면 골격을 잡을 때 따라야 할 구현 기준

### 0.2 이 문서가 결정하지 않는 것

아래 항목은 후속 문서에서 상세 정의한다.

| 항목 | 후속 문서 |
|---|---|
| 기능별 세부 입력값/검증/상태 전이 | PRD-004. 핵심 기능 요구사항 |
| 디자인 토큰, 카드 디자인, 폰트, 컬러, 애니메이션 | DESIGN-001. 디자인 시스템 |
| DB 테이블/컬럼/인덱스 | TSD-001. 기술 아키텍처 / DB / ERD |
| API Request/Response, Error Code | TSD-002. API 명세 |
| 기존 소모임/노션 데이터 이관 화면 | OPS-001. 데이터 이관 / 운영 / 릴리즈 |
| SEO 세부 키워드, sitemap, robots 정책 | PRD-004 또는 OPS-001에서 보완 |

### 0.3 상위 원칙

PRD-001, PRD-002의 결정을 따른다.

1. MVP는 모바일 퍼스트 반응형 웹으로 만든다.
2. 모바일 웹뷰에서도 주요 플로우가 끊기지 않아야 한다.
3. 기록 작성 진입은 1분 안에 도달할 수 있어야 한다.
4. 공개 페이지는 신규 방문자가 커뮤니티의 분위기를 이해할 수 있어야 한다.
5. 깊은 개인 정보와 멤버 전용 성장 기록은 외부에 노출하지 않는다.
6. `성장하는 사람들`은 단순 회원 목록이 아니라 성장 프로필 쇼케이스다.
7. UI/UX는 후속 DESIGN-001에서 계속 개선 가능해야 하며, 이 문서는 정보 구조와 접근 정책을 고정한다.
8. MVP에서 전체 통합 검색은 제외하고, 독서기록 라이브러리 안의 책 검색을 우선한다.
9. 랭킹, 점수, 상대 비교 UI는 제공하지 않는다.
10. URL은 가능하면 영어 path를 사용하고, 화면 표기는 한국어를 사용한다.

| 모바일 하단 메뉴 | `홈`, `라이브러리`, `모임`, `사람들`, `마이` |

| 성장하는 사람들 성격 | 회원 목록이 아니라 성장 프로필 쇼케이스 |
| 회원카드 디자인 | PRD-003에서는 정보 구조만 확정. 트렌디한 카드 UI는 DESIGN-001에서 구체화. |
| Guest 공개 프로필 | 표시명, 프로필 사진, 한 줄 소개, 관심 분야, 50살의 나, 성장 통계 요약, 최근 공개 활동 |
| Guest 비공개 프로필 | 생년월일, 가입 이유, 현재 고민, 3년 뒤 목표, 실행계획, 월간회고 |
| 나이 | MVP에서 수집/노출하지 않음 |
| 모임 Guest 공개 | 모임 목록/상세 기본 정보는 공개하되, 정확한 장소는 숨기고 지역 수준만 공개. 참석하기는 Member 전용. |
| 모임 참석자 목록 | Guest는 참석자 수와 매우 작은 비클릭 프로필 이미지 일부만 볼 수 있음. Member는 참석자 프로필 목록과 프로필 이동 가능. |
| 모임 후기 작성 | 참석 버튼 여부와 관계없이 Active Member는 작성 가능 |
| 홈 최근 성장 기록 | Guest는 공개 이벤트만, Member는 멤버 전용 이벤트까지 권한에 맞게 표시 |
| 전체 검색 | MVP 제외. 독서기록 라이브러리 안의 책 검색만 MVP 포함. |
| 마이페이지 상단 | 이번 달 참여 현황을 가장 먼저 보여준다. |
| Admin 진입 | 일반 메뉴에는 노출하지 않고, Admin 사용자에게만 프로필 메뉴/마이페이지에서 진입 링크 제공 |
| 모바일 보조 메뉴 | 모바일 상단 우측 햄버거 메뉴 제공. `모임 후기`, `소개`, `이용약관`, `개인정보처리방침` 접근 |
| 모임 참석자 프로필 미리보기 | 소모임 앱처럼 작은 원형 아바타 row로 노출. Guest는 클릭 불가, Member는 클릭 가능 |
| 독서기록 수정 권한 | 작성자만 수정 가능. Admin은 내용 직접 수정 불가, 숨김/삭제 관리만 가능 |

## 2. IA 개요

### 2.1 최상위 메뉴

```text
홈
├─ 독서기록 라이브러리
├─ 모임
├─ 성장하는 사람들
├─ 모임 후기
├─ 소개
├─ 마이페이지
└─ 관리자
```

### 2.2 전체 사이트맵

```text
/

/library
├─ 이달의 추천책
├─ 인기 도서 5권
├─ 최근 독서기록
├─ 책 검색
└─ 책 상세로 이동

/books
└─ 책 목록 / 검색 결과

/books/{bookId}
├─ 책 기본 정보
├─ 평균 평점
├─ 독서기록 수
├─ 읽은 사람
└─ 작성자별 독서기록 카드

/reading-records/new
└─ 독서기록 작성

/reading-records/{readingRecordId}/edit
└─ 독서기록 수정

/meetings
├─ 기본 모임
├─ 소소모임
└─ 모임 상세로 이동

/meetings/{meetingId}
├─ 모임 정보
├─ 참석자 목록
├─ 참석하기 / 참석 취소
├─ 후기 목록
└─ 후기 작성으로 이동

/meetings/new
└─ 소소모임 생성

/meetings/{meetingId}/edit
└─ 소소모임 수정 또는 Admin 모임 수정

/reviews
├─ 모임 후기 목록
└─ 후기 상세로 이동

/reviews/{reviewId}
└─ 모임 후기 상세

/reviews/new
└─ 모임 후기 작성

/people
├─ 성장하는 사람들 목록
├─ 관심 분야 필터
└─ 프로필 상세로 이동

/people/{memberId}
└─ 성장 프로필 상세

/mypage
├─ 이번 달 참여 현황
├─ 빠른 작성
├─ 내 최근 기록
└─ 내 프로필 요약

/mypage/profile
└─ 내 프로필 수정

/mypage/reading-records
└─ 내 독서기록 목록

/mypage/action-plans
└─ 내 월간 실행계획 목록 / 작성

/mypage/reflections
└─ 내 월간회고 목록 / 작성

/mypage/meetings
└─ 내가 참석한 모임 / 내가 만든 소소모임

/about
└─ 소개

/login
└─ 카카오 로그인 진입

/onboarding
└─ 초대코드 입력 / 약관 동의 / 프로필 입력

/admin
├─ 관리자 홈
├─ 회원 관리
├─ 초대코드 관리
├─ 관심 분야 태그 관리
├─ 이달의 추천책 관리
├─ 참여 현황 관리
├─ 모임 관리
└─ 후기 관리
```

## 4. 내비게이션 정책

### 4.1 PC 상단 내비게이션

PC와 태블릿 가로 화면에서는 상단 내비게이션을 사용한다.

```text
[부자습관 만들기 Growth Archive]

독서기록 라이브러리 | 모임 | 성장하는 사람들 | 모임 후기 | 소개

오른쪽: 로그인 / 마이페이지 / 관리자
```

#### 메뉴 순서

| 순서 | 메뉴명 | URL | 설명 |
|---:|---|---|---|
| 1 | 독서기록 라이브러리 | `/library` | 가장 먼저 만들 핵심 공개 라이브러리 |
| 2 | 모임 | `/meetings` | 월간 모임과 소소모임 |
| 3 | 성장하는 사람들 | `/people` | 성장 프로필 쇼케이스 |
| 4 | 모임 후기 | `/reviews` | 모임 분위기와 신뢰를 보여주는 후기 |
| 5 | 소개 | `/about` | 커뮤니티 철학, 운영 방식, 가입 안내 |

#### 우측 사용자 영역

| 사용자 상태 | 표시 |
|---|---|
| Guest | `로그인` 버튼 |
| Kakao User | `멤버 인증하기` 버튼 |
| Member | 프로필 이미지 + `마이페이지` |
| Admin | 프로필 메뉴 안에 `관리자` 링크 추가 |
| DEACTIVATED | 접근 제한 안내. 로그아웃 버튼 표시 |

### 4.2 모바일 하단 내비게이션

모바일 웹과 웹뷰에서는 하단 내비게이션을 기본으로 사용한다.

```text
홈 | 라이브러리 | 모임 | 사람들 | 마이
```

| 탭 | URL | 설명 |
|---|---|---|
| 홈 | `/` | 서비스 첫 화면 |
| 라이브러리 | `/library` | 독서기록 라이브러리 |
| 모임 | `/meetings` | 기본 모임/소소모임 |
| 사람들 | `/people` | 성장하는 사람들 |
| 마이 | `/mypage` 또는 `/login` | Guest는 로그인, Member는 마이페이지 |

#### 모바일 하단 내비게이션 정책

1. 하단 내비게이션은 모바일 화면에서 항상 접근 가능해야 한다.
2. 글쓰기 화면, 이미지 업로드 화면, 관리자 화면에서는 집중을 위해 숨길 수 있다.
3. `마이` 탭을 Guest가 누르면 `/login`으로 이동한다.
4. Admin 메뉴는 하단 내비게이션에 직접 노출하지 않는다.
5. `모임 후기`와 `소개`는 모바일 상단 우측 햄버거 메뉴와 푸터를 통해 접근한다.
6. 햄버거 메뉴에는 `모임 후기`, `소개`, `이용약관`, `개인정보처리방침`을 포함한다.
7. 햄버거 메뉴는 하단 탭에 넣지 않은 보조 탐색을 담당하며, 핵심 5개 하단 탭 구조를 흔들지 않는다.

### 4.3 모바일 햄버거 메뉴

모바일 화면에서는 하단 탭에 포함되지 않은 보조 메뉴 접근을 위해 상단 우측 햄버거 메뉴를 제공한다.

#### 햄버거 메뉴 항목

```text
모임 후기
소개
이용약관
개인정보처리방침
로그인 / 로그아웃 상태 액션
```

#### 정책

1. 하단 내비게이션은 핵심 사용 흐름을 담당한다.
2. 햄버거 메뉴는 정보성/보조 페이지 접근을 담당한다.
3. 모바일에서 `모임 후기`와 `소개`가 숨겨진 메뉴처럼 느껴지지 않도록 홈 섹션에서도 진입 CTA를 제공한다.
4. Admin 메뉴는 햄버거 메뉴에 기본 노출하지 않고, Admin role 사용자에게만 마이페이지 또는 프로필 메뉴에서 노출한다.

### 4.4 푸터

푸터는 모든 Public 페이지에 노출한다.

필수 링크:

```text
소개
독서기록 라이브러리
모임 후기
이용약관
개인정보처리방침
문의
```

MVP에서 문의는 별도 폼이 아니라 운영진 안내 문구 또는 외부 연락 수단으로 대체 가능하다.

## 6. 주요 사용자 흐름

### 6.1 Guest가 커뮤니티를 탐색하는 흐름

```text
홈 진입
↓
최근 성장 기록 확인
↓
이달의 추천책 또는 인기 도서 5권 클릭
↓
책 상세에서 여러 회원의 독서기록 확인
↓
블로그 원문 링크 이동
↓
성장하는 사람들 또는 모임 후기 탐색
↓
로그인 / 가입 안내 확인
```

#### 성공 조건

Guest는 로그인하지 않아도 다음을 이해할 수 있어야 한다.

1. 이 커뮤니티는 단순 독서모임이 아니라 성장 기록 아카이브다.
2. 회원들은 실제로 책을 읽고 기록을 남기고 있다.
3. 오프라인 모임과 소소모임이 운영되고 있다.
4. 어떤 방향을 가진 사람들이 함께하고 있는지 확인할 수 있다.

### 6.2 기존 회원이 이번 달 참여를 완료하는 흐름

```text
카카오 로그인
↓
마이페이지 진입
↓
이번 달 참여 현황 확인
↓
독서기록 작성 또는 실행계획 작성 클릭
↓
기록 작성 완료
↓
마이페이지에서 이번 달 참여 완료 확인
```

#### 성공 조건

Member는 마이페이지 첫 화면에서 다음을 5초 이내 이해할 수 있어야 한다.

1. 이번 달 참여 완료 여부
2. 독서기록 작성 여부
3. 실행계획 작성 여부
4. 지금 바로 작성할 수 있는 버튼

### 6.3 Member가 독서기록을 작성하는 흐름

```text
라이브러리 또는 마이페이지
↓
독서기록 작성 클릭
↓
책 검색
↓
책 선택
↓
한줄평, 블로그 URL, 대표 사진, 선택 평점 입력
↓
저장
↓
책 상세 / 내 프로필 / 최근 성장 기록에 반영
```

#### 성공 조건

1. 책 검색 후 중복 도서가 무분별하게 생성되지 않아야 한다.
2. 평점을 입력하지 않아도 저장할 수 있어야 한다.
3. 블로그 URL은 Guest도 접근 가능한 공개 링크로 사용된다.
4. 저장 후 이번 달 참여 현황이 자동 갱신되어야 한다.

### 6.4 Member가 소소모임을 만드는 흐름

```text
모임
↓
소소모임 만들기
↓
모임명, 설명, 일시, 장소, 정원, 대표 이미지 입력
↓
생성
↓
모임 목록과 최근 성장 기록에 반영
```

#### 성공 조건

1. Active Member는 누구나 소소모임을 생성할 수 있어야 한다.
2. 생성자만 해당 소소모임을 수정할 수 있어야 한다.
3. Admin은 숨김/삭제 관리가 가능해야 한다.

### 6.5 Admin이 참여 현황을 확인하는 흐름

```text
관리자 홈
↓
참여 현황 관리
↓
월 선택
↓
참여 완료 / 미참여 인원 확인
↓
미참여자 목록 확인
↓
필요 시 CSV 다운로드
```

#### 성공 조건

1. 미참여 기준은 `해당 월 독서기록 0건 AND 실행계획 0건`이다.
2. 커피 후원 기준은 투썸 아메리카노 1잔이다.
3. 모임 참석 여부는 MVP 참여 완료 조건에 포함하지 않는다.

## 7. 화면별 요구사항

아래 화면 요구사항은 UI 디자인을 고정하지 않는다.  
다만 각 화면에 필요한 정보, 액션, 권한, 빈 상태는 Codex 구현 기준으로 고정한다.

---

### 7.1 홈 `/`

#### 목적

서비스의 첫 인상을 만든다. Guest에게는 커뮤니티의 정체성과 활동성을 보여주고, Member에게는 빠르게 기록으로 진입할 수 있는 길을 제공한다.

#### 주요 대상

Guest, Member, Admin

#### 섹션 순서

MVP 기본값은 PRD-001의 홈 구성 순서를 따른다.

```text
1. Hero
2. 최근 성장 기록
3. 이달의 추천책
4. 인기 도서 5권
5. 최근 모임
6. 성장하는 사람들
7. 모임 소개 / 가입 안내
```

섹션 순서는 DESIGN-001에서 시각적 흐름에 따라 조정할 수 있으나, `Hero`, `최근 성장 기록`, `독서기록 라이브러리 진입`은 홈 상단부에 있어야 한다.

#### Hero 노출 정보

```text
부자습관 만들기
Growth Archive
읽고, 실행하고, 성장한 기록을 남기는 사람들
```

#### CTA

| 사용자 | CTA |
|---|---|
| Guest | 독서기록 둘러보기, 성장하는 사람들 보기, 로그인 |
| Kakao User | 멤버 인증하기 |
| Member | 독서기록 작성, 실행계획 작성, 마이페이지 |
| Admin | 관리자 페이지 |

#### 최근 성장 기록

| 이벤트 | Guest 노출 | Member 노출 |
|---|---:|---:|
| 독서기록 작성 | O | O |
| 모임 후기 작성 | O | O |
| 기본 모임 진행 | O | O |
| 소소모임 생성 | O | O |
| 월간 실행계획 작성 | X | O |
| 월간회고 작성 | X | O |

#### 빈 상태

| 상태 | 문구 예시 |
|---|---|
| 추천책 없음 | 아직 이달의 추천책이 등록되지 않았어요. |
| 최근 성장 기록 없음 | 아직 표시할 성장 기록이 없어요. 첫 기록을 남겨보세요. |
| 인기 도서 없음 | 독서기록이 쌓이면 인기 도서가 표시돼요. |

#### 인수 조건

```gherkin
Given 사용자가 Guest일 때
When 홈에 접근하면
Then Hero, 공개 최근 성장 기록, 이달의 추천책, 인기 도서 5권, 최근 모임, 성장하는 사람들 일부를 볼 수 있어야 한다.
```

```gherkin
Given 사용자가 Member일 때
When 홈에 접근하면
Then Guest 공개 정보에 더해 독서기록 작성과 실행계획 작성 CTA를 볼 수 있어야 한다.
```

---

### 7.2 독서기록 라이브러리 `/library`

#### 목적

회원들이 작성한 독서기록을 책 중심으로 탐색할 수 있게 한다.

#### 노출 정보

```text
이달의 추천책 3~5권
인기 도서 5권
최근 독서기록
책 검색 입력창
책 목록 또는 검색 결과 진입
```

#### CTA

| 사용자 | CTA |
|---|---|
| Guest | 책 상세 보기, 블로그 원문 보기 |
| Member | 독서기록 작성 |
| Admin | 추천책 관리로 이동 |

#### 정책

1. 전체 통합 검색은 MVP 제외다.
2. 라이브러리 내부 검색은 책 검색 중심이다.
3. 독서기록 상세 원문은 외부 블로그 URL로 이동한다.
4. 블로그 URL은 Guest도 접근할 수 있다.
5. `/library`는 독서기록 라이브러리 메인이다. 추천책, 인기 도서, 최근 독서기록, 책 검색 진입을 담당한다.
6. `/books`는 책 검색 결과/전체 책 목록 화면이다.
7. `/books/{bookId}`는 책 상세 화면이다.

#### 검색 흐름

```text
/library에서 책 검색
↓
/books?keyword=원씽 으로 이동
↓
검색 결과에서 책 선택
↓
/books/{bookId}로 이동
```

#### 빈 상태

| 상태 | 문구 예시 |
|---|---|
| 검색 결과 없음 | 검색 결과가 없어요. 다른 책 제목으로 검색해보세요. |
| 최근 독서기록 없음 | 아직 등록된 독서기록이 없어요. |

---

### 7.3 책 목록 / 검색 `/books`

#### 목적

책을 검색하고 책 상세로 이동할 수 있게 한다.

#### 노출 정보

```text
책 검색창
검색 결과 목록
책 표지
책 제목
저자
출판사
독서기록 수
평균 평점
```

#### 검색 정책

1. 외부 도서 API 연동 기반 검색을 사용한다.
2. 이미 DB에 등록된 책과 외부 검색 결과를 함께 처리할 수 있어야 한다.
3. 책 선택 후 해당 책이 DB에 없으면 저장할 수 있는 구조를 후속 PRD-004/TSD에서 정의한다.

---

### 7.4 책 상세 `/books/{bookId}`

#### 목적

하나의 책에 대해 여러 회원이 남긴 독서기록을 모아 보여준다.

#### 노출 정보

```text
책 표지
책 제목
저자
출판사
출간일
ISBN
평균 평점
독서기록 수
읽은 사람 수
이 책을 읽은 사람
작성자별 독서기록 카드
```

#### 작성자별 독서기록 카드

### 7.6 성장하는 사람들 `/people`

#### 목적

부자습관 만들기에는 어떤 사람들이 있고, 그 사람들이 어떤 방향으로 성장하고 있는지 보여준다.

이 화면은 단순 회원 목록이 아니다.  
**성장 프로필 쇼케이스**다.

#### 화면 컨셉

```text
성장하는 사람들
읽고, 실행하고, 성장한 기록을 남기는 사람들

회원 카드 그리드
```

#### 회원카드 Guest 노출 정보

```text
프로필 사진
표시명
한 줄 소개
관심 분야
50살의 나 1~2줄 요약
성장 통계 요약
최근 공개 활동 1개
```

#### 회원카드 Member 추가 노출 가능 정보

목록 카드에서는 과도하게 많은 정보를 보여주지 않는다.  
Member도 목록에서는 Guest와 거의 동일한 카드 구조를 본다. 깊은 정보는 상세에서 제공한다.

#### 카드 디자인 정책

1. PRD-003은 카드에 들어갈 데이터만 확정한다.
2. 카드의 시각 표현은 DESIGN-001에서 정의한다.
3. 카드 UI는 MVP 이후에도 쉽게 교체 가능해야 한다.
4. API는 디자인 변경에 대비해 카드에 필요한 정보를 구조적으로 제공해야 한다.

#### 정렬 정책

MVP 기본 정렬:

```text
최근 공개 활동이 있는 회원 우선
동률이면 가입일 최신순 또는 memberId 최신순
```

상대 비교처럼 보이는 랭킹 문구는 사용하지 않는다.

#### 필터

MVP 기본 필터:

```text
관심 분야 태그 필터
```

검색어 기반 사람 검색은 MVP 제외 또는 후순위로 둔다.

#### 빈 상태

```text
아직 보여줄 성장 프로필이 없어요.
첫 프로필을 완성해보세요.
```

### 7.9 모임 상세 `/meetings/{meetingId}`

#### 목적

모임 정보, 참석자, 후기, 참석 액션을 한 화면에서 제공한다.

#### 노출 정보

```text

설명

정원

참석자 프로필 이미지

```

#### Guest 노출 제한

| 항목 | Guest |
|---|---:|
| 모임명/설명/일시 | O |
| 장소 | 지역 수준만 공개. 정확한 장소/상세 주소 비공개 |
| 참석자 수 | O |
| 참석자 프로필 이미지 | 매우 작은 원형 아바타 일부만 공개. 이름/상세 정보 비공개 |
| 참석자 프로필 이동 | X |
| 참석하기 | 로그인 안내 |
| 후기 목록 | O |

#### 참석자 아바타 미리보기 정책

소모임 앱처럼 모임 상세 상단에 작은 원형 프로필 이미지를 row 형태로 보여준다.

```text
참석자 8명
[24px avatar] [24px avatar] [24px avatar] ... +3
```

1. Guest도 작은 아바타 row를 볼 수 있다. 단, 클릭할 수 없고 이름/프로필 상세는 표시하지 않는다.
2. Member는 아바타를 클릭하거나 참석자 목록을 열어 표시명과 프로필로 이동할 수 있다.
3. 이미지 크기, 겹침 간격, 최대 노출 개수는 DESIGN-001에서 정의한다. PRD-003 기본값은 24px, 최대 8개 노출이다.
4. 프로필 이미지가 없는 참석자는 기본 프로필 이미지를 사용한다.
5. 모임 카드/목록에서도 공간이 허용되면 동일한 작은 아바타 row를 사용할 수 있다.


#### Member 액션

```text
참석하기
참석 취소
후기 작성
공유하기
```

#### Admin 액션

```text
모임 수정
모임 숨김
모임 삭제
```

### 7.13 모임 후기 작성 `/reviews/new`

#### 목적

Member가 본인이 참여했거나 공유하고 싶은 모임의 후기를 작성한다. 시스템에서 참석 버튼을 눌렀는지 여부로 후기를 제한하지 않는다.

#### 권한 정책

1. Active Member는 모임 후기 작성 가능하다.
2. 시스템에서 참석 버튼을 누르지 않았어도 작성 가능하다.
3. 작성 화면에서 연결 모임을 선택해야 한다.
4. Admin도 Active Member로서 작성 가능하며, 별도 참석 검증은 하지 않는다.

#### 입력 항목

```text
연결 모임
제목
내용
사진 0~10장
```

#### 사진 공개 안내

후기 작성 화면에는 사진 업로드 전 다음 안내를 표시한다.

```text
업로드한 사진은 공개 모임 후기에 노출될 수 있어요.
함께 나온 사람들에게 공개 가능 여부를 확인해주세요.
```

MVP에서는 복잡한 사진 동의 시스템은 만들지 않는다. 단, 작성자가 공개 가능 여부를 인지하도록 안내하고, Admin은 후기/사진을 숨김 또는 삭제할 수 있어야 한다.

2. 작성하지 않아도 문제 없다.
3. 작성 여부는 참여 현황에 영향을 주지 않는다.
4. 언제든 수정 가능하다.
5. 멤버 전용 공개다.


### 7.20 온보딩 `/onboarding`

#### 목적

카카오 로그인 사용자를 Active Member로 전환한다.

#### 단계

```text
1. 초대코드 입력
2. 이용약관 / 개인정보처리방침 동의
3. 프로필 기본 정보 입력
4. 완료
```

#### 완료 후 이동

```text
/mypage
```

#### 정책

1. 일반 멤버용 활성 코드와 운영진용 활성 코드가 각각 1개씩 존재한다.
2. 가입 완료 전 진행 상태는 HttpOnly `signup_token`으로 관리한다.
3. 같은 브라우저에서 `signup_token`이 유효하면 온보딩 미완료 단계로 이어서 진행한다.
4. 로그아웃, 쿠키 삭제, 토큰 만료 시 가입 진행 상태는 폐기되며 초대코드 단계부터 다시 시작한다.
5. 온보딩 완료 전에는 Member 전용 기능을 사용할 수 없다.

## 9. 모바일 웹뷰 정책

### 9.1 기본 방향

MVP는 모바일 퍼스트 반응형 웹으로 구현한다.  
향후 웹뷰 앱, PWA, 하이브리드 앱으로 확장할 수 있도록 구조를 단순하게 유지한다.

### 9.2 모바일 레이아웃 원칙

1. 주요 CTA는 엄지 영역 안에 배치한다.
2. 하단 내비게이션을 기본 탐색 수단으로 제공한다.
3. 글쓰기 화면은 단일 컬럼으로 구성한다.
4. 이미지 업로드 화면은 모바일 카메라/앨범 접근을 고려한다.
5. 긴 목록은 무한 스크롤 또는 페이지네이션 중 하나를 PRD-004에서 확정한다.
6. 모달이 과도하게 겹치지 않도록 한다.
7. 카카오 로그인은 모바일 브라우저/웹뷰 환경에서 동작해야 한다.

### 9.3 웹뷰 고려 사항

1. Safe Area를 고려한다.
2. 하단 내비게이션이 시스템 제스처와 겹치지 않아야 한다.
3. 외부 블로그 링크는 새 창 또는 외부 브라우저 열기 정책을 후속 문서에서 확정한다.
4. 파일 업로드 권한 실패 시 안내 문구를 제공한다.
5. 향후 앱 전환을 위해 URL deep link 구조를 안정적으로 유지한다.

## 10. SEO / 공개 페이지 기본 정책

MVP에서는 모든 화면을 SEO 대상으로 삼지 않는다.  
검색 유입에 가치가 높은 페이지부터 우선한다.

### 10.1 Index 권장

```text
/
/library
/books
/books/{bookId}
/reviews
/reviews/{reviewId}
/about
```

### 10.2 Noindex 권장

```text
/login
/onboarding
/mypage/*
/admin/*
/reading-records/new
/reading-records/{id}/edit
```

### 10.3 Guest 접근 가능하지만 Noindex 권장

```text
/people
/people/{memberId}
```

이유:

1. 성장하는 사람들 페이지는 커뮤니티 분위기 전달에는 중요하다.
2. 다만 회원 개인 프로필이 검색엔진에 과도하게 노출되는 부담을 줄인다.
3. 실제 공개/색인 정책은 운영진과 회원 반응을 보고 Phase 2에서 재검토한다.

## 12. 인수 조건

### 12.1 내비게이션

```gherkin
Given 사용자가 모바일 화면으로 서비스에 접근했을 때
When 어떤 Public 페이지에 있더라도
Then 하단 내비게이션에서 홈, 라이브러리, 모임, 사람들, 마이로 이동할 수 있어야 한다.
```

```gherkin
Given 사용자가 PC 화면으로 서비스에 접근했을 때
When 상단 내비게이션을 보면
Then 독서기록 라이브러리, 모임, 성장하는 사람들, 모임 후기, 소개 메뉴가 순서대로 보여야 한다.
```

### 12.2 권한

```gherkin
Given 사용자가 Guest일 때
When `/mypage`에 접근하면
Then 로그인 화면으로 이동해야 한다.
```

```gherkin
Given 사용자가 Kakao User이지만 초대코드 인증 전일 때
When Member 전용 URL에 접근하면
Then `/onboarding`으로 이동해야 한다.
```

```gherkin
Given 사용자가 Member일 때
When `/admin`에 접근하면
Then 403 안내가 표시되어야 한다.
```

### 12.3 성장하는 사람들

```gherkin
Given 사용자가 Guest일 때
When 성장하는 사람들 목록을 보면
Then 회원카드에는 표시명, 프로필 사진, 한 줄 소개, 관심 분야, 50살의 나 요약, 성장 통계 요약, 최근 공개 활동이 보여야 한다.
```

```gherkin
Given 사용자가 Guest일 때
When 성장 프로필 상세에 접근하면
Then 생년월일, 가입 이유, 현재 고민, 3년 뒤 목표, 실행계획, 월간회고는 보여서는 안 된다.
```

```gherkin
Given 사용자가 Member일 때
When 다른 회원의 성장 프로필 상세에 접근하면
Then Member 전용 정보와 최근 실행계획/월간회고 일부를 볼 수 있어야 한다.
```

### 12.4 마이페이지

```gherkin
Given 사용자가 Member이고 이번 달 독서기록 0건, 실행계획 0건일 때
When 마이페이지에 접근하면
Then 참여 필요 상태와 독서기록 작성/실행계획 작성 CTA가 보여야 한다.
```

```gherkin
Given 사용자가 Member이고 이번 달 실행계획을 1건 작성했을 때
When 마이페이지에 접근하면
Then 이번 달 참여 완료 상태가 보여야 한다.
```

### 12.5 모임 후기

```gherkin
Given 사용자가 Active Member일 때
When 시스템상 참석 버튼을 누르지 않은 모임이라도
Then 해당 모임을 선택해 후기를 작성할 수 있어야 한다.
```


### 12.6 모바일 햄버거 메뉴

```gherkin
Given 사용자가 모바일 화면으로 서비스에 접근했을 때
When 상단 우측 햄버거 메뉴를 열면
Then 모임 후기, 소개, 이용약관, 개인정보처리방침 메뉴를 볼 수 있어야 한다.
```

### 12.7 모임 상세 Guest 공개 범위

```gherkin
Given 사용자가 Guest일 때
When 모임 상세 화면에 접근하면
Then 정확한 장소/상세 주소는 볼 수 없고 지역 수준 장소만 볼 수 있어야 한다.
```

```gherkin
Given 사용자가 Guest일 때
When 모임 상세 화면의 참석자 영역을 보면
Then 참석자 수와 작은 원형 아바타 미리보기는 볼 수 있지만, 참석자 이름과 프로필 상세 이동은 제공되지 않아야 한다.
```

### 12.8 독서기록 관리 권한

```gherkin
Given 사용자가 Admin이지만 독서기록 작성자가 아닐 때
When 독서기록 수정 URL에 접근하면
Then 내용을 직접 수정할 수 없어야 한다.
```

```gherkin
Given 사용자가 Admin일 때
When 관리자 화면에서 부적절한 독서기록을 관리하면
Then 해당 독서기록을 숨김 또는 삭제 처리할 수 있어야 한다.
```

## 13. Codex 구현 지침

Codex가 본 문서를 기반으로 구현할 때 다음 지침을 따른다.

### 13.1 라우팅

1. 이 문서의 URL 구조를 우선한다.
2. 임의로 새로운 최상위 URL을 만들지 않는다.
3. Open Questions가 남은 URL은 TODO 주석을 남기고 최소 구현으로 둔다.
4. 프로필 URL은 반드시 `/people/{memberId}`를 사용한다.

### 13.2 Layout

다음 레이아웃 컴포넌트를 분리한다.

```text
PublicLayout
MemberLayout
AdminLayout
OnboardingLayout
AuthLayout
```

### 13.3 Navigation

1. PC 상단 메뉴와 모바일 하단 메뉴는 별도 컴포넌트로 구현한다.
2. 로그인 상태에 따라 우측 사용자 영역과 `마이` 탭 동작이 달라져야 한다.
3. Admin 링크는 Admin role 사용자에게만 노출한다.

### 13.4 Access Guard

서버 또는 백엔드 API에서 최종 권한 검증을 해야 한다.  
프론트엔드 guard는 UX 보조 수단일 뿐이다.

필수 guard:

```text
requireMember
requireAdmin
redirectIfOnboardingIncomplete
blockDeactivatedUser
```

### 13.5 MVP 제외 기능

다음은 PRD-003 범위에서 구현하지 않는다.

## 15. 완료 기준

PRD-003 기준 MVP 화면 골격이 완료되었다고 판단하려면 다음 조건을 만족해야 한다.

```text
[ ] PC 상단 내비게이션이 정의된 순서대로 동작한다.
[ ] 모바일 하단 내비게이션이 홈/라이브러리/모임/사람들/마이로 동작한다.
[ ] 모바일 상단 햄버거 메뉴에서 모임 후기/소개/약관/개인정보처리방침에 접근할 수 있다.
[ ] Guest, Kakao User, Member, Admin별 접근 정책이 적용된다.
[ ] Public 페이지와 Member 전용 페이지가 분리되어 있다.
[ ] 성장하는 사람들 목록이 성장 프로필 쇼케이스 구조로 구현될 수 있다.
[ ] 프로필 상세에서 Guest/Member 노출 정보가 분리된다.
[ ] 마이페이지 첫 화면에서 이번 달 참여 현황을 확인할 수 있다.
[ ] 독서기록 작성 진입이 홈, 라이브러리, 마이페이지에서 가능하다.
[ ] 모임 목록/상세/소소모임 생성/후기 작성의 기본 흐름이 연결된다.
[ ] Guest는 모임의 정확한 장소를 볼 수 없고, 작은 참석자 아바타 미리보기만 볼 수 있다.
[ ] Admin은 독서기록 내용을 직접 수정할 수 없고 숨김/삭제 관리만 할 수 있다.
[ ] Admin 페이지의 진입 경로와 최상위 메뉴가 정의되어 있다.
[ ] 빈 상태, 에러 상태, 403, 404에 대한 기본 정책이 있다.
```
