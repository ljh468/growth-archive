# 0. 문서 역할과 구현 원칙

PRD-004는 Growth Archive MVP의 핵심 기능 요구사항을 정의한다.

PRD-001이 제품 비전과 MVP 범위를 정의하고, PRD-002가 사용자/권한/온보딩을 정의하며, PRD-003이 IA/URL/화면 구조를 정의한다면, PRD-004는 실제 기능 단위에서 아래 질문에 답한다.

```text
각 기능은 왜 필요한가?
누가 사용할 수 있는가?
사용자는 무엇을 입력하는가?
시스템은 무엇을 저장하고 계산하는가?
권한별로 무엇이 다르게 보이는가?
어떤 경우에 성공/실패로 판단하는가?
Codex가 구현할 때 임의로 결정하면 안 되는 것은 무엇인가?
```

## 0.3 상위 제품 원칙

Growth Archive MVP의 기능 설계는 아래 원칙을 따른다.

```text
1. 기록은 가볍게 남길 수 있어야 한다.
2. 책 검색이 독서기록 작성을 막으면 안 된다.
3. 독서기록은 장문 에디터가 아니라 블로그 링크 허브다.
4. 실행계획은 투두리스트가 아니라 이번 달의 선언이다.
5. 회고는 평가가 아니라 개인 성장 기록이다.
6. 참여 현황은 경쟁이 아니라 최소 참여를 확인하는 운영 장치다.
7. 랭킹, 포인트, 경쟁형 배지는 MVP에서 제외한다.
8. Guest에게는 커뮤니티 분위기를 보여주되, 깊은 개인 정보는 보호한다.
9. Admin은 운영을 돕지만, 회원의 기록 내용을 임의로 고치지 않는다.
10. 모바일 웹뷰에서도 핵심 기능을 사용할 수 있어야 한다.
11. 애매한 요구사항은 Codex가 임의 구현하지 않고 TODO/Open Question으로 남긴다.
```

# 1. 공통 기능 정책 `F-000`

## 1.1 사용자 유형 기준

PRD-004의 모든 권한은 PRD-002의 사용자 유형을 따른다.

| 사용자 유형 | 설명 |
|---|---|
| Guest | 비로그인 사용자 |
| Kakao User | 카카오 로그인은 했지만 초대코드/온보딩을 완료하지 않은 사용자 |
| Member | 카카오 로그인 + 초대코드 + 온보딩 완료 사용자 |
| Admin | ACTIVE_MEMBER 상태이면서 ADMIN Role을 가진 운영진 |

---

## 1.2 콘텐츠 상태 정책

MVP 콘텐츠는 기본적으로 아래 상태를 가진다.

| 상태 | 의미 | 사용자 노출 |
|---|---|---|
| ACTIVE | 정상 공개 또는 정상 사용 가능 | 권한에 따라 노출 |
| HIDDEN | Admin에 의해 숨김 처리됨 | 일반 사용자에게 비노출 |
| DELETED | 작성자 또는 Admin에 의해 삭제됨 | 일반 사용자에게 비노출 |

### 요구사항

- 작성자는 자신이 작성한 콘텐츠를 수정/삭제할 수 있어야 한다.
- Admin은 회원이 작성한 콘텐츠의 내용을 직접 수정하지 않는다.
- Admin은 운영상 필요한 경우 콘텐츠를 숨김 또는 삭제 처리할 수 있어야 한다.
- 삭제는 MVP에서 soft delete를 기본으로 한다.
- 숨김/삭제 콘텐츠는 공개 목록, 검색 결과, 최근 성장 기록에 노출되지 않아야 한다.

---

## 1.3 월 기준 정책

월간 실행계획, 월간 회고, 이번 달 참여 현황은 모두 `YYYY-MM` 단위로 관리한다.

### MVP 기본값

```text
월 시작: 매월 1일 00:00
월 종료: 매월 말일 23:59:59
시간대: Asia/Seoul
```

### 요구사항

- 모든 월간 계산은 Asia/Seoul 기준으로 처리한다.
- UI에서는 `2026년 7월` 형식으로 표시한다.
- API/DB에서는 `2026-07` 또는 해당 월의 기준일을 사용한다.
- 월간 참여 현황 계산 기준은 F-600을 따른다.

## 1.4 이미지 공통 정책

이미지 업로드 기능은 아래 기능에서 사용한다.

- 프로필 사진
- 독서기록 대표 사진
- 모임 대표 이미지
- 모임 후기 사진

### MVP 공통 정책

| 항목 | 정책 |
|---|---|
| 허용 형식 | jpg, jpeg, png, webp |
| 저장 형식 | WebP 변환 권장 |
| 원본 저장 | MVP 기본값: 원본 저장하지 않음 |
| 리사이징 | 업로드 시 자동 리사이징 |
| 파일명 | 서버 생성 고유 파일명 사용 |
| 접근 | 공개 이미지와 멤버 전용 이미지를 구분 가능해야 함 |

### 모임 후기 사진 특수 정책

- 모임 후기 사진은 최대 10장까지 업로드할 수 있어야 한다.
- 후기 사진은 Guest에게도 노출될 수 있으므로 작성 화면에서 공개 안내 문구를 표시해야 한다.

### 공개 안내 문구 기본값

```text
업로드한 사진은 공개 모임 후기에 노출될 수 있어요.
함께 나온 사람들에게 공개 가능 여부를 확인해주세요.
```

## 1.5 최근 성장 기록 공통 정책

최근 성장 기록은 홈 화면에서 커뮤니티가 살아 움직이고 있음을 보여주는 통합 피드다.

### 피드에 포함되는 이벤트

| 이벤트 | 생성 방식 | Guest 노출 | Member 노출 |
|---|---|---:|---:|
| 독서기록 작성 | 자동 | O | O |
| 월간 실행계획 작성 | 자동 | X | O |
| 월간 회고 작성 완료 | 자동 | X | O |
| 모임 후기 작성 | 자동 | O | O |
| 모임 진행 | 자동 또는 Admin 등록 | O | O |
| 소소모임 생성 | 자동 | O, 제한 정보 | O |

### 요구사항

- 최근 성장 기록은 최신순으로 정렬한다.
- Guest에게는 공개 가능한 이벤트만 보여준다.
- Member에게는 멤버 전용 이벤트까지 보여준다.
- 숨김/삭제된 콘텐츠와 연결된 이벤트는 노출하지 않는다.
- 피드 항목은 클릭 시 관련 상세 페이지로 이동해야 한다.
- 피드에 좋아요, 댓글, 반응 기능은 MVP에서 제공하지 않는다.
- 월간 회고는 슬롯 제공만으로 이벤트를 생성하지 않는다.
- 월간 회고 이벤트는 사용자가 실제 내용을 저장했을 때만 생성한다.

# 3. 독서기록 라이브러리 `F-200`

## 3.1 목적

독서기록 라이브러리는 회원들이 개인 블로그에 작성한 독서기록을 책 중심, 사람 중심으로 탐색할 수 있게 하는 기능이다.

현재 독서기록의 핵심 구조는 아래와 같다.

```text
책 검색
↓
책 선택 또는 임시 직접 등록
↓
평점 선택 입력
↓
한줄평 입력
↓
대표 사진 등록
↓
블로그 링크 등록
```

독서기록은 장문 본문을 서비스 내부에 작성하지 않는다.

---

## 3.2 책 검색 / 책 등록 `F-210`

### F-211. 외부 도서 API 검색

#### MVP 기본 API

MVP의 외부 도서 검색 기본 제공자는 아래로 확정한다.

```text
MVP 기본: 카카오 책 검색 API
Fallback 후보: 네이버 도서 검색 API
Phase 2 보조 후보: 알라딘 API
MVP 제외: 교보문고
```

#### 기술 구현 원칙

- 백엔드는 `BookSearchProvider` 인터페이스를 둔다.
- MVP 구현체는 `KakaoBookSearchProvider`로 한다.
- 카카오 API 장애, 품질 이슈, 정책 변경에 대비하여 향후 `NaverBookSearchProvider`를 추가할 수 있는 구조로 설계한다.
- Frontend는 특정 외부 API 제공자를 알 필요가 없다.
- Frontend는 백엔드의 내부 책 검색 API만 호출한다.

#### 요구사항

- Member는 독서기록 작성 시 외부 도서 API를 통해 책을 검색할 수 있어야 한다.
- 검색 결과는 책 제목, 저자, 출판사, 표지 이미지, ISBN 정보를 포함해야 한다.
- 사용자가 책을 선택하면 시스템은 내부 Book 데이터가 있는지 확인해야 한다.
- 동일 ISBN의 Book이 이미 있으면 기존 Book을 재사용해야 한다.
- 동일 ISBN의 Book이 없으면 새 Book을 생성해야 한다.
- 외부 API 응답값은 내부 Book 모델에 맞게 정규화되어 저장되어야 한다.

#### 검색 결과 노출 정보

| 필드 | 필수 여부 | 설명 |
|---|---:|---|
| title | 필수 | 책 제목 |
| author | 권장 | 저자 |
| publisher | 권장 | 출판사 |
| thumbnailUrl | 권장 | 책 표지 이미지 |
| isbn | 강력 권장 | 중복 방지 기준 |
| publishedDate | 선택 | 출간일 |
| source | 필수 | KAKAO |

#### 검증 조건

- 검색어는 최소 1자 이상이어야 한다.
- 검색 결과가 없으면 빈 상태와 직접 등록 CTA를 표시해야 한다.
- 외부 API 오류 시 사용자에게 재시도 메시지를 보여줘야 한다.
- 외부 API 오류가 발생해도 이미 저장된 내부 Book 검색 결과가 있으면 우선 보여줄 수 있다.

#### 빈 상태 문구

```text
검색 결과가 없어요.
직접 책 정보를 입력해서 독서기록을 남길 수 있어요.
```

#### 오류 문구

```text
책 검색 중 문제가 발생했어요. 잠시 후 다시 시도해주세요.
```

#### 인수 조건

```gherkin
Given Member가 독서기록 작성 화면에 있을 때
When 책 제목을 검색하면
Then 카카오 책 검색 API 기반 검색 결과가 목록으로 표시되어야 한다.

Given 검색 결과에서 책을 선택했을 때
When 동일 ISBN의 책이 내부 DB에 없으면
Then Book이 새로 생성되어야 한다.

Given 검색 결과에서 책을 선택했을 때
When 동일 ISBN의 책이 내부 DB에 있으면
Then 기존 Book을 재사용해야 한다.
```

### F-212. 책 검색 결과 없음 처리 / 임시 직접 등록

MVP에서는 외부 도서 API 검색을 기본으로 한다.

단, 책 검색이 독서기록 작성을 막으면 안 된다. 외부 API에서 책을 찾지 못하는 경우에도 Member는 직접 책 정보를 임시 등록하고 독서기록을 작성할 수 있어야 한다.

#### MVP 정책

- 검색 결과가 없을 경우 Member가 직접 책을 임시 등록할 수 있다.
- 직접 등록된 책은 `UNVERIFIED` 상태로 저장한다.
- 직접 등록된 책은 독서기록 작성에 즉시 사용할 수 있다.
- 직접 등록된 책도 책 상세 페이지를 가질 수 있다.
- 직접 등록된 책은 Admin 또는 향후 스케줄러를 통해 검증/보강/병합할 수 있게 설계한다.

#### 직접 등록 책 필드

| 항목 | 필수 여부 | 설명 |
|---|---:|---|
| 책 제목 | 필수 | 사용자가 직접 입력 |
| 저자 | 필수 | 모르면 `미상` 입력 가능 여부는 TSD/UX에서 결정 |
| 출판사 | 선택 | 직접 입력 |
| 표지 이미지 | 선택 | 업로드 또는 기본 이미지 |
| 출간일 | 선택 | 직접 입력 |

#### 직접 등록 책 상태

| 상태 | 의미 |
|---|---|
| VERIFIED | 외부 API 또는 Admin에 의해 검증된 책 |
| UNVERIFIED | Member가 직접 임시 등록한 책 |

#### 직접 등록 책 source

| source | 의미 |
|---|---|
| KAKAO | 카카오 책 검색 API로 생성 |
| MANUAL | Member가 직접 등록 |
| ADMIN | Admin이 직접 정리/보정 |

#### 향후 스케줄러 고려

TSD-001에서 아래 확장 가능성을 고려한다.

```text
1. UNVERIFIED 책 목록을 주기적으로 조회한다.
2. 카카오 책 검색 API로 동일/유사 도서를 재검색한다.
3. ISBN 또는 제목/저자 유사도 기반으로 후보를 찾는다.
4. 자동 병합은 MVP에서 하지 않는다.
5. Admin 검토 대상 목록으로 제공한다.
```

MVP에서는 스케줄러 구현은 필수가 아니다. 단, DB 설계는 향후 스케줄러와 Admin 검증 흐름을 막지 않아야 한다.

#### 이유

이 정책은 아래 원칙 때문이다.

```text
책 검색 실패가 글쓰기 실패가 되면 안 된다.
기록은 불완전해도 남길 수 있어야 한다.
데이터 품질은 이후 Admin/스케줄러로 보완한다.
```

#### 인수 조건

```gherkin
Given Member가 책을 검색했을 때
When 검색 결과가 없으면
Then 직접 책 등록 버튼이 보여야 한다.

Given Member가 직접 책 제목과 저자를 입력했을 때
When 저장하면
Then UNVERIFIED 상태의 Book이 생성되어야 한다.

Given UNVERIFIED Book이 생성되었을 때
When Member가 독서기록 저장을 완료하면
Then 해당 Book과 연결된 ReadingRecord가 생성되어야 한다.
```

## 3.3 독서기록 작성 `F-220`

### 권한

| 사용자 | 작성 가능 여부 |
|---|---:|
| Guest | X |
| Kakao User | X |
| Member | O |
| Admin | O, Member 권한으로 작성 |

### 입력 항목

| 항목 | 필수 여부 | 설명 | 검증 |
|---|---:|---|---|
| 책 | 필수 | 외부 검색 선택 또는 임시 직접 등록 | 필수 |
| 평점 | 선택 | 1~5 정수 별점 | 선택 입력 |
| 한줄평 | 필수 | 짧은 독서 소감 | 최대 길이 TSD/UX에서 결정 |
| 대표 사진 | 선택 | 책 표지/인증 사진 모두 가능 | 이미지 정책 준수 |
| 블로그 URL | 필수 | 개인 블로그 원문 링크 | URL 형식 검증 |

### 대표 사진 정책

- 대표 사진은 책 표지 사진 또는 실제 독서 인증 사진 모두 가능하다.
- 책 표지는 Book의 외부 API 썸네일로 이미 존재할 수 있다.
- 독서기록 대표 사진은 회원이 남긴 기록의 온도를 보여주는 용도다.
- 대표 사진이 없으면 책 표지 이미지를 fallback으로 사용할 수 있다.

### 평점 정책 `F-224`

- 평점은 선택 입력이다.
- 평점을 입력하지 않아도 독서기록을 저장할 수 있어야 한다.
- MVP 기본 평점 단위는 1~5 정수다.
- 0.5점 단위 평점은 MVP 이후 검토한다.
- 평균 평점 계산 시 평점이 없는 독서기록은 제외한다.
- 인기 도서 계산 시 평점 없는 독서기록도 독서기록 수에는 포함한다.

### 블로그 URL 정책

- 블로그 URL은 Guest도 볼 수 있다.
- URL은 새 창 또는 외부 브라우저로 이동해야 한다.
- 서비스 내부에 장문 독후감 에디터는 제공하지 않는다.
- MVP에서는 블로그 URL의 메타데이터 자동 수집은 필수가 아니다.

### 저장 후 반영 위치

독서기록 저장 후 아래 위치에 반영되어야 한다.

- 독서기록 라이브러리 최근 독서기록
- 책 상세 작성자별 독서기록 목록
- 작성자 성장 프로필 최근 독서기록
- 홈 최근 성장 기록
- 작성자의 월간 참여 현황
- 인기 도서 TOP5 계산 데이터

### 인수 조건

```gherkin
Given Member가 독서기록 작성 화면에 있을 때
When 책, 한줄평, 블로그 URL을 입력하고 저장하면
Then 독서기록이 생성되어야 한다.

Given Member가 평점을 입력하지 않았을 때
When 독서기록을 저장하면
Then 평점 없이 독서기록이 생성되어야 한다.

Given Member가 이번 달 독서기록을 1건 작성했을 때
When 이번 달 참여 현황을 확인하면
Then 참여 완료로 표시되어야 한다.
```

### 인수 조건

```gherkin
Given Admin이 다른 회원의 독서기록 상세에 접근했을 때
When 관리 메뉴를 열면
Then 숨김/삭제 액션만 가능하고 내용 수정 액션은 제공되지 않아야 한다.

Given 작성자가 자신의 독서기록에 접근했을 때
When 수정 버튼을 누르면
Then 독서기록 수정 화면으로 이동해야 한다.
```

## 3.5 독서기록 라이브러리 메인 `F-240`

독서기록 라이브러리 메인은 `/library`에서 제공한다.

### 구성 섹션

| 순서 | 섹션 | 설명 |

### 인기 도서 TOP5 표시 정책

- 인기 도서가 5권 미만이면 등록된 만큼만 표시한다.
- 인기 도서가 0권이면 섹션을 숨긴다.

### 50살의 나

- 프로필 상단에 크게 노출한다.
- 언제든 수정 가능하다.
- Guest도 볼 수 있다.
- 목록에서는 1~2줄 요약, 상세에서는 전체 내용을 보여준다.

### 성장 통계

| 통계 | 계산 기준 |
|---|---|
| 독서기록 수 | ACTIVE 독서기록 수 |
| 실행계획 수 | ACTIVE 실행계획 수 |
| 월간 회고 수 | 작성 완료된 회고 수 |
| 모임 후기 수 | ACTIVE 후기 수 |
| 소소모임 개설 수 | 생성한 ACTIVE 소소모임 수 |

### 최근 기록 노출

프로필 상세에는 최근 기록을 3개까지만 노출한다.

| 기록 | Guest | Member |
|---|---:|---:|
| 최근 독서기록 3개 | O | O |
| 최근 모임 후기 3개 | O | O |
| 최근 실행계획 3개 | X | O |
| 최근 월간 회고 3개 | X | O |

나머지 기록은 더보기 또는 별도 탭으로 연결할 수 있다.

# 5. 월간 실행계획 `F-400`

## 5.1 목적

월간 실행계획은 회원이 이번 달 해보고 싶은 것을 자유롭게 선언하는 기능이다.

실행계획은 투두리스트나 OKR이 아니다.

```text
실행계획 = 이번 달의 선언
```

---

## 5.2 작성 정책 `F-410`

### 권한

| 사용자 | 작성 가능 여부 |
|---|---:|
| Guest | X |
| Kakao User | X |
| Member | O |
| Admin | O, Member 권한으로 작성 |

### 월별 작성 제한

- Member는 월별 실행계획 1개를 작성할 수 있다.
- 같은 월에 이미 실행계획이 있으면 새로 만들지 않고 기존 실행계획을 수정한다.
- 실행계획은 자유 입력이다.

### 입력 항목

| 항목 | 필수 여부 | 설명 |
|---|---:|---|
| 대상 월 | 필수 | 기본값 현재 월 |
| 제목 | 선택 | 예: 7월 실행계획 |
| 내용 | 필수 | 자유 입력 |

### 공개 범위

- 월간 실행계획은 Member 전용이다.
- Guest에게는 내용과 작성 이벤트를 공개하지 않는다.

### 수정/삭제

- 작성자는 언제든 수정할 수 있다.
- 작성자는 삭제할 수 있다.
- Admin은 숨김/삭제 관리만 가능하고 내용을 직접 수정하지 않는다.

### 참여 현황 반영

- 해당 월 실행계획이 1건 이상 존재하면 참여 완료 조건을 충족한다.
- 실행계획이 삭제/숨김 처리되면 참여 현황은 재계산된다.

### 인수 조건

```gherkin
Given Member가 2026년 7월 실행계획을 작성하지 않았을 때
When 실행계획 작성 화면에서 내용을 저장하면
Then 2026년 7월 실행계획이 생성되어야 한다.

Given Member가 2026년 7월 실행계획을 이미 작성했을 때
When 다시 실행계획 작성 화면에 접근하면
Then 기존 실행계획 수정 화면으로 진입해야 한다.

Given Member가 2026년 7월 실행계획을 작성했을 때
When 이번 달 참여 현황을 확인하면
Then 참여 완료로 표시되어야 한다.
```

# 6. 월간 회고 `F-500`

## 6.1 목적

월간 회고는 회원이 한 달을 돌아보며 성장 기록을 남기는 기능이다.

월간 회고는 작성하지 않아도 문제가 없다.

```text
회고 = 평가가 아니라 기록
```

---

## 6.2 회고 슬롯 정책 `F-510`

### 기능 요구사항

- 매월 모든 ACTIVE_MEMBER에게 해당 월 회고 작성 진입점이 제공되어야 한다.
- UI에서는 `2026년 7월 회고 작성 가능` 같은 슬롯처럼 보여줄 수 있다.
- 실제 DB row를 월초에 생성할지, 작성 시 생성할지는 TSD-001에서 결정한다.
- 기능 관점에서는 사용자가 매월 `YYYY년 M월 회고`를 작성할 수 있어야 한다.

### 이벤트 생성 정책

- 월간 회고 슬롯 제공만으로 최근 성장 기록 이벤트를 생성하지 않는다.
- 월간 회고 작성 이벤트는 사용자가 실제 내용을 저장했을 때만 생성한다.
- 모든 내용이 비어 있는 회고는 저장하지 않는다.

### 작성 의무

- 월간 회고는 작성 의무가 없다.
- 작성하지 않아도 참여 현황 미완료로 처리하지 않는다.
- 커피 후원 대상 계산에 포함하지 않는다.

---

## 6.3 작성 정책 `F-520`

### 월별 작성 제한

- Member는 한 달에 회고 1개를 작성할 수 있다.
- 이미 해당 월의 회고가 있으면 새로 생성하지 않고 기존 회고를 수정한다.

### 입력 항목

| 항목 | 필수 여부 | 설명 |
|---|---:|---|
| 대상 월 | 필수 | 기본값 현재 월 |
| 이번 달 잘한 것 | 선택 | 자유 입력 |
| 아쉬운 점 | 선택 | 자유 입력 |
| 다음 달 집중할 것 | 선택 | 자유 입력 |

### 저장 가능 조건

- 모든 내용이 비어 있으면 저장하지 않는다.
- 최소 1개 필드에는 내용이 있어야 저장할 수 있다.

### 공개 범위

- 월간 회고는 Member 전용이다.
- Guest에게는 내용과 작성 이벤트를 공개하지 않는다.

### 수정/삭제

- 작성자는 언제든 수정할 수 있다.
- 작성자는 삭제할 수 있다.
- Admin은 숨김/삭제 관리만 가능하고 내용을 직접 수정하지 않는다.

### 인수 조건

```gherkin
Given Member가 마이페이지에 접근했을 때
When 이번 달 회고를 작성하지 않았으면
Then 이번 달 회고 작성 가능 상태가 보여야 한다.

Given Member가 회고를 작성하지 않았을 때
When 이번 달 참여 현황을 확인하면
Then 회고 미작성은 참여 미완료 사유가 아니어야 한다.

Given Member가 월간 회고 내용을 저장했을 때
When 최근 성장 기록을 확인하면
Then Member에게만 월간 회고 작성 완료 이벤트가 보여야 한다.
```

# 7. 이번 달 참여 현황 `F-600`

## 7.1 목적

이번 달 참여 현황은 회원이 최소한의 커뮤니티 참여를 했는지 확인하는 기능이다.

이 기능은 벌점 경쟁 시스템이 아니라, 커뮤니티의 작은 불씨를 유지하는 운영 장치다.

---

## 7.2 최종 참여 규칙 `F-610`

매월 아래 둘 중 하나 이상 충족하면 참여 완료다.

```text
1. 독서기록 1건 작성
또는
2. 월간 실행계획 1건 작성
```

### 참여 완료 조건

| 조건 | 완료 인정 |
|---|---:|
| 해당 월 ACTIVE 독서기록 1건 이상 | O |
| 해당 월 ACTIVE 실행계획 1건 이상 | O |
| 독서기록 0건 + 실행계획 0건 | X |
| 월간 회고 작성 | X, 참여 현황에는 반영하지 않음 |
| 모임 참석 | X, 참여 현황에는 반영하지 않음 |
| 모임 후기 작성 | X, 참여 현황에는 반영하지 않음 |

### 커피 후원 기준

참여 미완료자는 운영 규칙상 아래 커피 후원 대상이 된다.

```text
투썸 아메리카노 1잔
```

MVP에서는 결제/정산 기능을 제공하지 않는다. 시스템은 대상자 확인까지만 지원한다.

---

## 7.3 마이페이지 참여 현황 `F-620`

### 노출 위치

마이페이지 최상단에 노출한다.

### 노출 정보

| 정보 | 설명 |
|---|---|
| 대상 월 | 예: 2026년 7월 |
| 독서기록 작성 수 | 해당 월 ACTIVE 독서기록 수 |
| 실행계획 작성 여부 | 해당 월 ACTIVE 실행계획 존재 여부 |
| 참여 상태 | 참여 완료 / 참여 필요 |
| 안내 문구 | 참여 완료 축하 또는 커피 후원 안내 |

### 완료 상태 문구

```text
이번 달 참여 완료 🎉
```

### 미완료 상태 문구

```text
이번 달 참여가 아직 필요해요.
독서기록 1건 또는 실행계획 1건을 남기면 완료돼요.
```

### 커피 후원 안내 문구

```text
월말까지 참여가 없으면 투썸 아메리카노 1잔 후원 대상이 될 수 있어요.
```

## 7.4 Admin 참여 현황 관리 `F-630`

### 목적

운영진이 월별 참여 완료자와 미참여자를 쉽게 확인할 수 있게 한다.

### 노출 정보

- 대상 월
- 전체 대상 회원 수
- 참여 완료 수
- 참여 미완료 수
- 완료율
- 미참여자 목록
- 각 회원별 독서기록 작성 수
- 각 회원별 실행계획 작성 여부

### 미참여자 목록 노출 정보

- 프로필 이미지
- 표시명
- 닉네임
- 참여 상태
- 독서기록 수
- 실행계획 작성 여부
- 커피 후원 기준 문구: 투썸 아메리카노 1잔
- 운영 메모

### 운영 메모

Admin은 월별 미참여자에 대해 운영 메모를 남길 수 있다.

예시:

```text
신규 가입자라 이번 달 제외
장기 출장
운영진이 별도 확인 완료
```

운영 메모는 Member에게 노출하지 않는다.

### CSV 다운로드

Admin은 미참여자 목록을 CSV로 다운로드할 수 있어야 한다.

#### CSV 기본 컬럼

```text
memberId, displayName, nickname, readingRecordCount, hasActionPlan, participationStatus, coffeeSupportItem, adminMemo
```

### 인수 조건

```gherkin
Given Admin이 2026년 7월 참여 현황을 조회했을 때
When Member A가 7월 독서기록 1건을 작성했다면
Then Member A는 참여 완료로 표시되어야 한다.

Given Admin이 2026년 7월 참여 현황을 조회했을 때
When Member B가 7월 독서기록과 실행계획을 모두 작성하지 않았다면
Then Member B는 미참여자로 표시되어야 한다.
```

## 7.5 참여 현황 대상자 정책 `F-640`

### MVP 기본값

- 대상 월에 `ACTIVE_MEMBER` 상태인 회원을 참여 현황 계산 대상으로 한다.
- `DEACTIVATED` 회원은 계산 대상에서 제외한다.
- 신규 가입자는 가입 다음 달부터 참여 현황 계산 대상이 된다.

### participationStartMonth

TSD-001에서 회원별 참여 계산 시작 월 필드를 고려한다.

```text
participationStartMonth = YYYY-MM
```

예시:

```text
가입일: 2026-07-20
participationStartMonth: 2026-08
```

### 기존 회원 이관 고려

기존 회원을 웹서비스로 이관하는 경우 실제 모임 참여 시작일과 온보딩 완료일이 다를 수 있다.

따라서 Admin이 필요 시 `participationStartMonth`를 조정할 수 있는 구조를 TSD/OPS에서 검토한다.

### 인수 조건

```gherkin
Given Member가 2026년 7월 20일에 가입했을 때
When 2026년 7월 참여 현황을 계산하면
Then 해당 Member는 계산 대상에서 제외되어야 한다.

Given Member가 2026년 7월 20일에 가입했을 때
When 2026년 8월 참여 현황을 계산하면
Then 해당 Member는 계산 대상에 포함되어야 한다.
```

# 8. 모임 / 소소모임 `F-700`

## 8.1 목적

모임 기능은 오프라인 활동을 웹에 연결하고, 회원들이 정기모임과 소소모임에 쉽게 참석 의사를 표시할 수 있게 한다.

MVP의 모임 기능은 결제/복잡한 모집 기능이 아니라 아래를 목표로 한다.

```text
모임 정보 확인
참석하기
참석자 확인
소소모임 만들기
모임 후기 연결
```

---

## 8.2 모임 유형 `F-710`

| 유형 | 설명 | 생성 주체 |
|---|---|---|
| 월간 독서기록 모임 | 정기 독서모임 | 시스템 자동 생성 또는 Admin |
| 월간 실행계획 모임 | 정기 실행계획/수다 모임 | 시스템 자동 생성 또는 Admin |
| 소소모임 | 회원이 자유롭게 만드는 소규모 모임 | Member |

---

## 8.3 모임 상태 `F-715`

모임은 아래 상태를 가진다.

| 상태 | 의미 | 일반 노출 |
|---|---|---:|
| SCHEDULED | 예정된 모임 | O |
| HELD | 진행 완료된 모임 | O |
| CANCELED | 취소된 모임 | 제한 노출 가능 |
| HIDDEN | Admin 숨김 | X |
| DELETED | 삭제 | X |

### 상태 정책

- 기본 생성 상태는 `SCHEDULED`다.
- 모임 종료 후 `HELD` 전환은 자동 또는 Admin 수동 처리로 구현할 수 있다.
- `HELD` 전환 자동화 여부는 TSD-001에서 결정한다.
- `HIDDEN`과 `DELETED`는 일반 목록에 노출하지 않는다.
- 후기는 `SCHEDULED` 또는 `HELD` 모임에 연결 가능하다.
- 후기 작성이 시스템 참석 여부로 제한되지 않기 때문에, 모임 상태가 아직 `HELD`가 아니어도 Admin 운영 상황에 따라 후기 작성이 가능할 수 있다.

---

## 8.4 기본 정기모임 자동 생성 `F-720`

### 요구사항

- 매월 기본 정기모임 2개가 자동 생성되어야 한다.
- 자동 생성 시점은 매월 1일 00:10 KST다.
- 해당 월 정기모임이 이미 생성되어 있으면 중복 생성하지 않는다.
- 자동 생성된 모임은 Admin이 운영 목적상 수정할 수 있어야 한다.

### 자동 생성 규칙

```text
매월 1일 00:10 KST에 해당 월 정기모임 2개 자동 생성
이미 생성되어 있으면 중복 생성하지 않음
```

### 자동 생성 대상

| 모임 | 기본 날짜 | 기본 시간 | 기본 상태 |
|---|---|---|---|
| 월간 독서기록 모임 | 매월 2번째 일요일 | 오전 10:00 | SCHEDULED |
| 월간 실행계획 모임 | 매월 4번째 일요일 | 오전 10:00 | SCHEDULED |

### Admin 수정 가능 항목

정기모임은 운영 일정에 맞게 변경될 수 있으므로 Admin은 아래 항목을 수정할 수 있다.

- 모임명
- 일시
- 지역 수준 장소
- 정확한 장소
- 설명
- 정원
- 대표 이미지
- 비용
- 상태

### 중복 방지 기준

TSD-001에서는 아래 조합으로 중복 생성을 방지하는 unique constraint 또는 application-level guard를 고려한다.

```text
meetingType + targetMonth
```

정기모임은 동일 월에 동일 유형이 1개만 자동 생성되는 것을 기본값으로 한다.

| 모임 유형 | 필수 | 독서기록/실행계획/소소모임 |

| 일시 | 필수 | 날짜와 시간 |
| 지역 수준 장소 | 필수 | Guest 공개용, 예: 하남 미사 |
| 정확한 장소 | 선택 | Member 전용, 예: 카페명/상세 주소 |

| 정원 | 선택 | 없으면 제한 없음 |

| 비용 | 선택 | 기본값 0원 |
| 상태 | 필수 | 기본값 SCHEDULED |

### 비용 표시 정책

- 비용 필드는 제공한다.
- 기본값은 0원이다.
- 비용이 0원이면 Guest/Member 화면에서는 비용 영역을 숨긴다.
- 비용이 1원 이상이면 비용을 표시한다.
- 결제 기능은 MVP에서 제공하지 않는다.

## 8.6 모임 목록 / 상세 공개 정책 `F-730`

### Guest 공개

- 참석자 표시명
- 참석자 프로필 링크

```text
일부 인원만 미리보기
정확한 장소 비공개
```

Member에게는 참석자 목록에서 표시명과 프로필 이동을 제공할 수 있다.

## 8.7 참석하기 `F-740`

### 권한

| 사용자 | 참석 가능 여부 |
|---|---:|
| Guest | X |
| Kakao User | X |
| Member | O |
| Admin | O |

### 동작

- Member가 `참석하기`를 누르면 즉시 참석자 목록에 추가된다.
- 운영진 승인 절차는 없다.
- 참석 후 버튼은 `참석 취소`로 변경된다.
- 정원이 있는 경우 정원 초과 참석은 불가하다.
- 대기자 기능은 MVP에서 제외한다.
- 시스템 참석 여부는 모임 후기 작성 권한을 제한하지 않는다.

### 인수 조건

```gherkin
Given Member가 모임 상세에 접근했을 때
When 참석하기 버튼을 누르면
Then 참석자 목록에 해당 Member가 추가되어야 한다.

Given 정원 10명인 모임에 이미 10명이 참석 중일 때
When 다른 Member가 참석하기를 누르면
Then 정원 마감 메시지가 표시되어야 한다.
```

# 9. 모임 후기 `F-800`

## 9.1 목적

모임 후기는 외부 방문자에게 커뮤니티 분위기와 신뢰를 보여주는 공개 콘텐츠다.

독서기록이 지식 자산이라면, 모임 후기는 관계와 분위기의 증거다.

---

## 9.2 작성 권한 `F-810`

### 핵심 정책

모임 후기 작성은 시스템 참석 여부로 제한하지 않는다.

실제로 참석 버튼을 누르지 않았지만 오프라인 모임에 참석하는 경우가 있으므로, Active Member는 본인이 참여했거나 공유하고 싶은 모임을 선택해 후기를 작성할 수 있다.

### 권한

| 사용자 | 작성 가능 여부 |
|---|---:|
| Guest | X |
| Kakao User | X |
| Member | O |
| Admin | O, Member 권한으로 작성 |

### 연결 모임

- 후기는 특정 모임에 연결하는 것을 권장한다.
- 연결 가능한 모임은 `SCHEDULED` 또는 `HELD` 상태의 모임이다.
- 모임 연결 없이 후기를 작성할지 여부는 PRD-004 MVP에서는 제외한다.

---

## 9.3 후기 작성 입력 항목 `F-820`

| 항목 | 필수 여부 | 설명 |
|---|---:|---|
| 연결 모임 | 필수 | 후기 대상 모임 |
| 제목 | 필수 | 후기 제목 |
| 내용 | 필수 | 자유 입력 |
| 사진 | 선택 | 최대 10장 |

### 사진 정책

- 사진은 최대 10장까지 업로드할 수 있다.
- 업로드 시 WebP 변환과 리사이징을 적용한다.
- 원본 저장은 MVP 기본값으로 하지 않는다.
- 첫 번째 사진을 대표 이미지로 사용한다.
- 대표 이미지 변경 기능은 MVP 이후 검토한다.
- 사진 업로드 영역에 공개 안내 문구를 표시한다.

## 10.3 초대코드 관리

`docs/prd/PRD_002_Users_Auth_Permissions_Onboarding.md` 기준:

```text
활성 초대코드는 1개만 유지
운영진이 새 코드로 변경하면 기존 코드는 즉시 무효화
```

### 요구사항

- Admin은 현재 활성 초대코드를 볼 수 있어야 한다.
- Admin은 초대코드를 변경할 수 있어야 한다.
- 초대코드 변경 시 기존 코드는 즉시 비활성화된다.
- 초대코드는 대소문자 구분 없이 검증한다.

## 10.5 책 관리 / UNVERIFIED 관리

### 목적

Member가 직접 등록한 책은 기록 작성을 막지 않기 위한 임시 데이터다. Admin은 데이터 품질을 높이기 위해 직접 등록 책을 확인할 수 있어야 한다.

### MVP 최소 요구사항

- Admin은 `UNVERIFIED` 책 목록을 볼 수 있어야 한다.
- Admin은 책의 기본 정보를 수정할 수 있다.
- Admin은 책을 `VERIFIED` 처리할 수 있다.
- 중복 책 병합 UI는 MVP 이후로 미룰 수 있다.

### 향후 확장

- 스케줄러 기반 외부 API 재검색
- 유사 책 후보 추천
- Admin 승인 기반 병합

# 12. 성장 이벤트 설계 고려 `F-1200`

성장 이벤트는 향후 성장 로드맵을 만들기 위한 기반이다.

MVP에서 시각화 로드맵은 제공하지 않지만, 이벤트 생성 구조는 이후 확장을 막지 않아야 한다.

---

## 12.1 자동 생성되는 성장 이벤트

| 원인 | 이벤트 타입 | Guest 노출 | Member 노출 |
|---|---|---:|---:|
| 독서기록 작성 | READING_RECORD_CREATED | O | O |
| 실행계획 작성 | ACTION_PLAN_CREATED | X | O |
| 월간 회고 작성 완료 | REFLECTION_CREATED | X | O |
| 모임 참석 | MEETING_ATTENDED | X | O |
| 소소모임 생성 | MEETING_CREATED | O, 제한 | O |
| 모임 후기 작성 | MEETING_REVIEW_CREATED | O | O |

### 주의

- 월간 회고 슬롯 제공은 성장 이벤트가 아니다.
- 실제 회고 저장 완료 시에만 `REFLECTION_CREATED` 이벤트를 생성한다.
- 이벤트 저장 테이블을 MVP에서 반드시 별도로 만들지는 TSD-001에서 결정한다.
- 단, 홈 최근 성장 기록을 구현할 수 있는 조회 전략은 필요하다.

# 13. 예외 케이스 / 오류 상태

## 13.1 카카오 책 검색 API 장애

### 상황

책 검색 API가 응답하지 않거나 오류를 반환한다.

### 요구사항

- 사용자에게 오류 메시지를 보여준다.
- 재시도할 수 있어야 한다.
- 이미 내부 DB에 저장된 Book 검색 결과가 있으면 우선 보여줄 수 있다.
- API 장애 상황에서도 Member가 직접 책을 임시 등록할 수 있는 CTA를 제공할 수 있다.

### 오류 문구

```text
책 검색 중 문제가 발생했어요. 잠시 후 다시 시도해주세요.
직접 책 정보를 입력해서 기록을 남길 수도 있어요.
```

## 13.2 이미지 업로드 실패

### 요구사항

- 실패한 이미지를 사용자에게 알려준다.
- 나머지 입력값은 유지해야 한다.
- 모임 후기에서 일부 이미지 업로드가 실패하면 실패 이미지만 다시 업로드할 수 있어야 한다.

## 13.3 권한 없음

### 상황

Guest 또는 Kakao User가 Member 기능에 접근한다.

### 요구사항

- Guest는 로그인 화면으로 이동한다.
- Kakao User는 초대코드/온보딩 화면으로 이동한다.
- 접근이 제한된 이유를 간단히 안내한다.

## 13.4 정원 마감

### 상황

### 요구사항

- 참석하기 버튼을 비활성화한다.
- 정원 마감 문구를 보여준다.
- 대기자 기능은 MVP 제외다.

# 15. Codex 구현 지침

Codex는 이 문서를 기반으로 구현할 때 아래 지침을 따라야 한다.

```text
1. PRD-001~003의 결정사항을 우선한다.

6. 직접 등록 책은 UNVERIFIED로 저장한다.
7. 월간 참여 현황 계산은 독서기록 1건 또는 실행계획 1건 규칙만 사용한다.
8. 신규 가입자는 가입 다음 달부터 참여 현황 계산 대상이다.
9. 월간 회고는 참여 현황 계산에 포함하지 않는다.
10. 소소모임 수정은 생성자만 가능하다.
11. Admin은 소소모임 숨김/삭제만 가능하다.
12. 모임 후기 작성은 시스템 참석 여부로 제한하지 않는다.
13. 모임 후기 사진은 최대 10장으로 제한한다.
14. Guest에게 정확한 모임 장소를 노출하지 않는다.
15. Guest에게 참석자 프로필은 작은 이미지 일부만 노출하고 이름/클릭은 제공하지 않는다.
16. 구현 중 애매한 부분은 TODO와 질문으로 남긴다.
```

# 16. MVP 완료 체크리스트

## 독서기록

- [ ] Member가 카카오 책 검색 API 기반으로 책을 검색할 수 있다.
- [ ] 검색 결과에서 책을 선택해 Book을 생성/재사용할 수 있다.
- [ ] 검색 결과가 없을 때 Member가 직접 책을 임시 등록할 수 있다.
- [ ] 직접 등록된 책은 UNVERIFIED 상태로 저장된다.
- [ ] Member가 독서기록을 작성할 수 있다.
- [ ] 평점 없이 독서기록을 저장할 수 있다.
- [ ] 블로그 URL은 Guest도 볼 수 있다.
- [ ] 작성자만 독서기록을 수정할 수 있다.
- [ ] Admin은 독서기록을 숨김/삭제할 수 있지만 내용 수정은 할 수 없다.
- [ ] 책 상세에서 작성자별 독서기록 토글을 볼 수 있다.
- [ ] 인기 도서 TOP5가 표시된다.
- [ ] 이달의 추천책이 표시된다.

## 성장 프로필

- [ ] 성장하는 사람들 목록이 표시된다.
- [ ] 회원카드에 공개 정보가 표시된다.
- [ ] `/people/{memberId}` 프로필 상세가 표시된다.
- [ ] 50살의 나가 프로필 상단에 크게 노출된다.
- [ ] Member에게만 깊은 개인 정보가 표시된다.

## 실행계획 / 회고

- [ ] Member가 월간 실행계획을 작성할 수 있다.
- [ ] 월별 실행계획은 1개만 유지된다.
- [ ] 실행계획은 Member 전용이다.
- [ ] Member가 월간 회고를 작성할 수 있다.
- [ ] 회고를 작성하지 않아도 참여 현황 미완료가 되지 않는다.
- [ ] 회고 이벤트는 실제 저장 시에만 생성된다.

## 참여 현황

- [ ] 독서기록 1건 이상이면 참여 완료다.
- [ ] 실행계획 1건 이상이면 참여 완료다.
- [ ] 둘 다 없으면 참여 필요다.
- [ ] 신규 가입자는 가입 다음 달부터 참여 대상이다.
- [ ] Admin은 미참여자 목록을 볼 수 있다.
- [ ] Admin은 CSV를 다운로드할 수 있다.
- [ ] Admin은 미참여자 운영 메모를 남길 수 있다.

## 모임 / 소소모임

- [ ] 매월 1일 00:10 KST에 정기모임 2개가 자동 생성된다.
- [ ] 중복 정기모임이 생성되지 않는다.
- [ ] 독서기록 모임은 매월 2번째 일요일 오전 10시 기본값이다.
- [ ] 실행계획 모임은 매월 4번째 일요일 오전 10시 기본값이다.
- [ ] Admin은 정기모임 정보를 수정할 수 있다.
- [ ] Member는 소소모임을 생성할 수 있다.
- [ ] 생성자는 소소모임을 수정할 수 있다.
- [ ] Admin은 소소모임을 숨김/삭제할 수 있지만 내용 수정은 할 수 없다.
- [ ] Member는 모임에 참석하기/취소할 수 있다.
- [ ] Guest에게는 지역 수준 장소만 공개된다.
- [ ] Guest에게는 아주 작은 프로필 이미지 일부만 노출된다.

## 모임 후기

- [ ] Active Member는 시스템 참석 여부와 관계없이 후기를 작성할 수 있다.
- [ ] 후기는 특정 모임에 연결된다.
- [ ] 후기 사진은 최대 10장이다.
- [ ] 사진 공개 안내 문구가 표시된다.
- [ ] Guest도 공개 후기를 볼 수 있다.
- [ ] 작성자만 후기를 수정할 수 있다.
- [ ] Admin은 후기를 숨김/삭제할 수 있지만 내용 수정은 할 수 없다.

## 관리자

- [ ] Admin은 초대코드를 변경할 수 있다.
- [ ] 활성 초대코드는 1개만 유지된다.
- [ ] Admin은 관심 분야 태그를 관리할 수 있다.
- [ ] Admin은 추천책을 관리할 수 있다.
- [ ] Admin은 UNVERIFIED 책 목록을 볼 수 있다.
- [ ] Admin은 회원 콘텐츠 내용을 직접 수정할 수 없다.
